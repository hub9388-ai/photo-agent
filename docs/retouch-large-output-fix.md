# 调色应用失败：无损结果误用了上传限制

## 真实原因

失败任务 `f9e1efed-7c0f-47ef-84d2-b4333ede20bd` 的异常发生在
`adjust_image → write_layer_image → assets.create_from_bytes → images.probe`。
像素计算已完成，保存 PNG 时触发 `ImageRejected: 文件超过 20 MB 上限`。
原会话 `1766fd56-238b-4dd9-b22a-b74cfe46e51e` 仍为 revision=1，未采用失败结果。

原始 JPEG：5464×3070，10,625,761 字节。使用该次实际参数生成 PNG 后为
29,619,581 字节（约 28.25 MiB），比源 JPEG 大。与 Post 转换方向、跳过去朦胧或模型 Key 无关。
此前 64×48 小图验收没有覆盖这种大尺寸输出，这是测试覆盖缺口。

## 修复

- 上传文件仍为 20 MiB 上限。
- 由工具或生成服务产生的内部工作图独立校验，上限 256 MiB；像素上限仍为 50,000,000。
- 在完整解码前检查像素总量。保留原尺寸、无损 PNG 和透明度，不为绕过限制缩图或转 JPEG。
- `ImageRejected` 作为明确的任务失败原因返回，避免全部显示“执行失败，请重试”。
- 本地适配补丁同步更新；未提交或推送 GitHub。

## 验证

`tests/test_retouch_output_limits.py` 使用真正超过 20 MiB 的 RGBA PNG，验证上传拒绝、
内部保存接受且字节不变、透明度/尺寸不变、像素上限仍有效、具体错误可返回。
