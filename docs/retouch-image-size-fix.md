# 调色后图像输入超过 10MB（2026-10-18）

## 现象与原因

“亮度提高20% → 猫咪变圆润”计划中，调色成功，局部替换在发送模型前失败，提示输入超过10MB。调色代码输出 RGBA PNG；原始 JPEG 文件大小无法代表后续无损 PNG 的大小。

同一猫咪原图经上游实际 `adjust(brightness=0.2)` 本地复现：

| 阶段 | 字节数 |
| --- | ---: |
| 原始 JPEG | 3,825,456 |
| 调色结果 PNG | 16,262,328 |
| 模型传输副本 JPEG（quality=95） | 3,513,697 |

尺寸始终为 3072×4096。上述为本地复现，不声称已从数据库提取并测量用户失败任务的具体对象。

## 修复与边界

在 DashScope 适配器内，超过10MB的输入自动建立传输副本。不透明照片编码为 JPEG，含透明像素的图片编码为 WebP，并分档尝试质量直到满足大小限制。不缩放、不改写存储中的原文件或调色结果。压缩可能损失细节，语义生成本身也不保证像素级保真。如果压缩后仍超限则在本地返回明确错误，不提交模型。

10 项离线适配/异常测试通过，其中新增不透明图压缩后的尺寸与文件限制检查、透明图 Alpha 保留检查。原图字节未改变。本轮模型调用数为 0，不能据此宣称生成结果质量或对话编辑全链路已验收。

验证报告：`.test_artifacts/retouch-transport/report.json`。补丁 `integrations/retouch-photoai.patch` 已更新并通过反向应用检查，API 与 Worker 已重启加载。

用户可在现有计划点击一次“重试失败步骤”，继续局部替换；不应重新提交整条调色指令，否则可能再次增加亮度。
