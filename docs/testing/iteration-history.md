# 历史测试与项目迭代记录

测试不仅用于发布前检查，也参与了产品方案的调整。这份记录将此前保存的诊断、失败、阻塞、修复与验收串联起来，帮助理解“为什么这样设计”，并保留当时尚未验证的范围。

**当前自动化回归快照仍为 197 条用例、10 个模块，全部通过**，见[测试总览](README.md)。下表是按能力演进整理的历史节点，不把相同用例的多次执行、阶段测试数量或单次模型请求累加到 197 中。同日记录未全部保留精确时间，因此表格不声称是逐分钟的完整时间线。

## 2. 三个适合深入学习的迭代案例

### 案例 A：为什么工具成功仍可能是 Agent 失败

1. **用户观察**：希望画面更沉闷，结果却像提亮了暗部。
2. **证据定位**：Post 的 `Shadows2012=-10`，实际 `adjust_image` 入参为 `shadows=+0.12`；执行状态是 succeeded。
3. **测试目标变化**：从“请求有没有成功”扩展到“工具参数有没有遵守方向和能力约定”。
4. **方案调整**：支持项交给代码转换；不支持项明确跳过；用户在滑杆中预览微调，减少模型自由换算。
5. **验证链**：历史错误回放能被判定器识别 → 转换函数满足方向和跳过规则 → 草稿把实际用户值传给工具 → 浏览器检查应用后像素及导出。
6. **未解决范围**：摄影软件与 Pillow 的视觉幅度等价性、结果是否符合用户审美，仍需样本校准和人工评估。

### 案例 B：为什么小图通过还要补大图测试

1. **初始验收**：64×48 合成图走通 API、队列和 ZIP 导出，输出像素正确。
2. **用户反馈**：真实大图点击应用失败。
3. **定位结果**：调色计算完成，但无损 PNG 比原 JPEG 大，内部保存误用了上传文件大小限制。
4. **覆盖缺口**：小图验证了流程，却未覆盖输出膨胀与存储限制的交互。
5. **修复及验收**：分开上传与内部结果策略，保留像素上限；用超过 20MiB 的真实 PNG 增加回归，再用问题图在独立会话检查保存、下载和撤销。
6. **学习点**：按图片尺寸、编码、透明度和生命周期设计测试；“上传成功”不意味着后续生成与保存也能成功。

### 案例 C：为什么人像问题不能只改提示词

1. **用户观察**：人物修改后出现透明缺口，且身形效果不自然。
2. **只读审计**：拆层输入由角点颜色阈值生成，包含大块舞台背景；并未得到可靠的人物专用局部区域。
3. **方案取舍**：先阻止不可靠拆层自动进入人像编辑；保留原图，要求用户确认局部选区，不继续叠加坏候选。
4. **分层测试**：后端在模型调用前拦截 → 蒙版与选区外像素检查 → 独立账号 API 等待确认 / 取消 → 笔刷加减和撤销逻辑回归。
5. **保留的边界**：防护通过不等于瘦身自然。也没有用“same pose / expression”等提示词替代身份、服装和肢体保真验收。

## 3. 如何阅读历史数量与状态

- **保留失败与 blocked**：它们解释了为什么补环境、改交互或新增测试，不应从记录中删除后只留下“通过”。
- **阶段数量是当时快照**：旧文档里的 5、8、10、12、21、35 项，可能是同一测试文件逐步增加、某个子集或脚本检查点。没有完整版本化清单时，不相加，也不据此计算质量提升百分比。
- **区分真实请求、模拟与重放**：合成图真实 API 能验证服务与像素链路；Mock 能覆盖难稳定触发的错误；历史重放能验证规则，但都不能单独证明真实模型审美质量。
- **不倒改旧证据**：人工正向样例不写成真实修复执行；后来的通过也不覆盖先前失败轨迹。
- **旧文档的“尚未实施 / 未推送 / 尚未浏览器验收”是当时状态**：对应后续进展看本页及[当前总览](README.md)，不能用后来完成的工作反推当时已验收。
- **历史记录不等于现在仍在线**：真实模型额度、服务配置和外部依赖会变化；本次未重跑的实测均标为历史验证，不保证原环境当下仍可用。

## 4. 后续每次迭代如何继续记录

建议每条记录保留以下字段：

| 字段 | 要回答的问题 |
| --- | --- |
| 用户场景与目标 | 谁在做什么，期望结果是什么？ |
| 发现方式与版本 | 用户反馈、人工体验还是自动测试发现？对应哪个版本？ |
| 失败证据 | 实际输出、工具入参、错误码或状态是什么？ |
| 原因与方案取舍 | 原因有哪些证据，为什么采用这项最小修改？ |
| 测试设计 | 正常、异常和边界输入是什么，如何判断通过？ |
| 验证结果 | 本地 / 公网、Mock / 真实服务 / 真实模型，哪些通过或未执行？ |
| 固化位置 | 新增到哪个测试文件或评测目录，是否进入回归？ |
| 结论与剩余风险 | 这次证明了什么，仍不能证明什么？ |

已有记录缺失的字段保持未知，不补造早期版本号、用户量、失败率、调用成本或精确耗时分布。私人图片、账号凭据与数据库继续留在本地；仓库展示脱敏结论、方法与代码。
