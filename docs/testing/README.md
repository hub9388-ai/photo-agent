### A. Agent 协作与上下文

- **作用**：确认用户从素材筛选流转到 Post、Coach、Plan 时，任务、照片与上下文没有丢失或串用。
- **怎么测**：替换模型客户端与回复，构造用户输入和素材选择；使用合成图片、临时数据目录，驱动统一入口、交接和多轮追问。不是向真实模型批量提问。
- **覆盖内容**：意图路由、统一入口、交接确认、非法选择、失败恢复、流式回复回退、规划追问、Coach 历史状态更新、Post / Coach 服务映射。
- **结果**：33 条通过。例如素材搜索只命中一张时能成为当前焦点，交接失败后能恢复选择，后续问题沿用约定的上下文。
- **说明了什么**：固定场景下编排与状态传递符合测试约定；不代表任意自然语言都能被模型正确识别。
- **代码**：`test_entrypoints`、`test_handoff`、`test_end_to_end`、`test_asset_recovery`、`test_post_chat`、`test_plan_followup`、`test_coach_lifecycle`、`test_agent_services_stage5`。完整链接与逐例数量见索引。

### B. 模型与外部服务接入

- **覆盖内容**：运行时配置、参考链接 / 高德 POI 响应适配、阿里凭据选择、模糊配置拒绝、模块导入、知识缺失降级和接口暴露边界。
- **结果**：21 条通过。凭据选择和异常配置遵守已有规则，知识读取失败可按约定降级。
- **说明了什么**：配置治理与接入层防护有效；不能证明账号余额充足、网络稳定，或所有模型版本均兼容。
- **代码**：`test_runtime`、`test_provider_adapter`、`test_qwen_image_config`、`test_settings`、`test_legacy_imports`、`test_skills_mcp_stage85`。

### C. 输出协议与界面文案

- **说明了什么**：程序能处理这些协议变体；不能证明任意模型输出均可恢复，也不是页面视觉质量评分。

### F. 事件日志与部署保护

- **作用**：让任务可追踪，避免演示预算被并发突破，或预算存储出错后仍放行付费调用。
- **怎么测**：捕获事件输出，读取临时 JSONL；以多连接并发访问临时预算数据库，并构造中间件请求和预检输入。
- **覆盖内容**：事件输出、追踪字段、输入摘要截断、原子预算、超限拦截和部署预检。
- **结果**：8 条通过。固定并发场景下只放行预算内次数，预算读取失败不会放行计费请求。
- **说明了什么**：这些预算与追踪规则有回归保护；不是完整反滥用或渗透测试。当前纯前端 Netlify 演示不调用模型，预算中间件属于完整系统部署能力。
- **代码**：`test_events`、`test_trace`、`test_demo_deployment`。

### G. 后期建议转换与原图传递

- **作用**：把 Post 的参考建议变为可微调初值，避免方向反转、擅自替代和把其他照片的建议传入当前会话。
- **怎么测**：直接调用转换函数并输入参数化边界数据；模拟保存结果、媒体读取和 Pillow 调用，检查原始参数、目标参数、来源与版本校验。
- **覆盖内容**：阴影正负方向、非法范围 / NaN / 字符串拒绝、黑色色阶和去朦胧跳过、来源匹配、原图字节传递、格式回退、草稿过期拦截、审计字段不传入像素工具。
- **结果**：22 条通过。示例阴影 `-10` 转为 `shadows=-0.1`；不支持项返回跳过原因；用户微调后的值准确传给像素函数。
- **说明了什么**：转换与交接遵守代码约定；幅度仍是近似初值，不能声称等同 Lightroom 或已经通过摄影审美校准。
- **代码**：[建议转换](../../backend/tests/test_retouch_advice.py)、[原图传递](../../backend/tests/test_retouch_source.py)、[调色草稿](../../tests/test_retouch_adjust_draft.py)。

### H. 人物保护、笔刷与修图执行

- **作用**：减少局部人物编辑破坏原图、错误选区和失败结果被采用的风险。
- **怎么测**：生成小尺寸图片、不同笔触与透明蒙版，比较像素；用 Mock / AsyncMock 模拟提供方、事务和失败，不对真人照片发模型请求。
- **覆盖内容**：明确宠物圆润可无选区进入待确认、已有选区沿用、多图层澄清；阻止简化拆层、人物要求当前有效选区并等待确认、选区外像素保持、画笔与套索区别、擦除、透明缺口拦截、超时和事务回滚、格式与大小限制。
- **结果**：35 条通过。未授权路径在调用模型或写入前被阻止，选区外像素按约定保持，异常候选不被采用。
- **说明了什么**：编辑边界与异常处理有自动化保护；不能证明瘦身结果自然、身份不变或生成模型在真实照片上稳定。文件名 `test_retouch_live.py` 指实时接入相关代码，其测试本身是离线模拟。
- **代码**：[人物](../../tests/test_retouch_portrait.py)、[笔刷](../../tests/test_retouch_brush.py)、[接入与失败处理](../../tests/test_retouch_live.py)、[结果限制](../../tests/test_retouch_output_limits.py)。

### I. Agent 执行语义评测判定器

- **说明了什么**：针对这一执行约定，规则判定器能捕获已定义错误；不是完整 Agent Benchmark，也不是模型综合能力排名。

### J. 浏览器产品流程

- **作用**：确认 HR 或面试官实际点击页面时，分析、修图、保存、学习和规划可以连贯体验。
- **怎么测**：Playwright 启动真实 Chrome，点击原页面按钮，在修图 iframe 中发送指令、确认计划、操作滑杆；检查实际图片像素、ZIP、浏览器缓存、控制台错误和网络请求。
- **结果**：10 条通过，分别覆盖：
  1. 三栏分析 → 素材库 → 学习练习 → 历史恢复。
  2. 预置圆润修改 → 确认计划 → 保存素材 → 刷新恢复。
  3. 西湖规划生成 → 切换方案 → 采用 → 刷新恢复。
  4. 不支持的生成需求给出反馈，保留当前图片。
  5. 静态页面和编辑器深链接可访问。
  6. 滑杆修改真实像素、撤销 / 重做、ZIP 导出。
  7. 预置分析偏好影响建议，重置不清理真实模式缓存。
  8. 不支持的偏好 / 目的地不返回无关固定结果。
  9. 首页按任务直接进入现有页面，导航与五阶段顺序一致，手机宽度无横向溢出。
  10. 首页进入分析，再导入原编辑器，照片、任务 ID 与 Post 建议初值完整传递。
- **说明了什么**：演示流程可操作，测试中没有意外后台请求、外部请求或页面异常；分析和生成结果来自预置数据，不能据此声称真实模型线上链路通过。本次本地验证与此前同组 8 条公网验证分别记录，不重复计数。
- **代码**：[浏览器用例](../../frontend/tests/product-demo.spec.ts)。

## 3. 历史 Agent 错误如何变成可重复评测

案例：Post 建议阴影 `-10`，历史工具却执行 `shadows=+0.12`，还把黑色色阶、去朦胧擅自替换为亮度、锐化等。工具状态是成功，但行为不符合约定。

| 对象 | 本次结果 | 应如何理解 |
| --- | --- | --- |
| 历史真实执行轨迹 | 15 个检查点中 5 个不满足，退出码 1 | 成功复现和识别已知错误；不是测试程序崩溃 |
| 人工正向轨迹 | 15 个检查点满足，退出码 0 | 证明判定器能接纳合规输入；不是模型修复实测 |
| 生产转换代码回放 | 15 个检查点满足，退出码 0 | 生产转换输出符合方向 / 跳过约定；没有执行图片工具 |

这三组是同一业务案例的不同验证输入，不是 3 条真实用户任务，也不能计算成“Agent 成功率从 0% 提升到 100%”。转换逻辑、浏览器调色和真实生成质量属于不同证据层，不能相互替代。

学习顺序：[案例说明](../../evaluations/001-shadow-direction/README.md) → [故障复盘](../../evaluations/001-shadow-direction/review.md) → [判定器](../../evaluations/001-shadow-direction/evaluate.py) → [转换回放](../../evaluations/001-shadow-direction/check_converter.py) → [面试讲述](../../evaluations/001-shadow-direction/interview.md)。案例目录中保留的历史状态描述不代替本页最新的分层验证结果。

## 5. 如何自己运行和复盘

### 一次运行主要测试并生成清单

前提：主系统 Python 测试依赖、独立修图环境及固定源码补丁、前端 npm 依赖和 Chrome 已准备好；`frontend/out-demo` 已构建。修图初始化见[集成说明](../retouch-integration.md)。无需启动 Docker / FastAPI 或准备模型余额；脚本不会运行上述真实模型 smoke。

```powershell
# 首次或前端修改后，在 frontend/ 构建静态演示
cd frontend
npm.cmd ci
npm.cmd run build:demo
cd ..

# Windows：默认查找本项目现有的独立修图 Python 环境
python scripts/test_report.py --run

# 若环境放在其他位置，显式传路径
python scripts/test_report.py --run --retouch-python <独立修图环境中的python路径>
```

脚本将运行主系统、修图、判定器、浏览器、3 个前端离线检查、Pillow core 和规则回放。明细放入 Git 忽略的 `.test_artifacts/test-inventory/`；生成公开的 `case-inventory.md` 与脱敏 `results.json`。遇到某套测试失败会停止生成新的汇总，先检查对应日志，避免把旧的通过报告当成新结果。已发布快照保留各套验证时间和测试源码 SHA256。

仅从已有运行报告重新汇总：

```powershell
python scripts/test_report.py
```

这个命令**不会运行测试**，不能据此声称新代码已通过验证。添加测试文件后也要更新脚本的模块归属表；未分类文件会直接报错，防止漏计。

### 按层学习与运行

```powershell
# 主系统：148 条；默认不混入独立修图后端的同名 app 包
python -m pytest -q

# 独立修图：38 条，需固定源码补丁和该环境的依赖
.\.test_artifacts\retouch-runtime\Scripts\python.exe -m unittest discover -s tests -p 'test_retouch*.py' -v

# 判定器自身：6 条，无模型或数据库依赖
python -m unittest discover -s evaluations/001-shadow-direction -p test_evaluate.py -v

# 浏览器：10 条，需要静态构建与 Chrome
cd frontend
npm.cmd run test:demo
cd ..

# 历史失败重放：预期退出码 1，表示抓到了已知错误

```

建议从一条真实问题开始学习：**用户目标 → 失败现象 → 执行记录 → 判断标准 → 构造输入 → 自动断言 → 修复后回归 → 明确未覆盖范围**。可以先阅读阴影方向案例，再阅读人物保护和浏览器导出测试。

## 6. 面试中如何解释这些结果

可以表述为：“围绕 Agent 上下文流转、建议到工具参数的转换、人物编辑保护及核心产品流程，整理并复跑了 202 条自动化用例；对‘工具成功但方向错误’的问题建立离线执行轨迹评测，区分程序正确性与生成质量。”

仍需补充的评估：

- 多照片、多风格和异常输入的独立 Agent 案例集，以及人工标注的一致判定标准。
- 人像自然度、身份保持、背景一致性等生成质量评估；已有像素保护检查不能替代这些标准。
- 真实模型稳定性、延迟、成本、长期多轮表现和多用户并发验证。
- 产品效果验证：用户是否更容易理解建议、完成修图或持续练习。目前没有用户实验数据，不虚构转化率、留存或满意度提升。

目前没有接入 EvalScope。这些是 pytest / unittest / Playwright 测试和自定义规则评测，后续可以基于已有案例规范研究评测框架接入。
