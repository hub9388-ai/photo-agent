# 规划联网兜底

当规划请求的地点没有返回高德候选，或天气没有返回可用预报时，自动查询网页资料。高德正常返回的能力不额外搜索；明确跳过的能力也不搜索。

## 实现

- `photo_provider_adapter.collect_provider_context` 分别判断地点与天气缺失，每类最多一次查询，每次最多三条结果。
- 搜索先尝试 DuckDuckGo HTML；请求失败、验证页或无结果时，改用 Bing RSS。单个请求超时 8 秒、读取最多 1 MB，不打开搜索结果里的目标网页。两个能力都缺失时最多四次搜索端点请求，搜索阶段的网络等待预算最多约 32 秒，另加高德和模型耗时。
- 查询只使用城市、目标地点、题材和日期；不传照片、用户完整对话、账号或模型凭据。该外发范围已由项目维护者确认。
- 标题与摘要以 `web_search` 字段进入现有规划模型上下文，保留内部 URL 和用途以供排错。它们不会写入高德的 POI 或天气预报字段，也不会因此获得地图已核验标记。
- 沿用现有页面与接口，不新增来源列表。模型指令要求优先给地点顺序、时间段、拍摄角度、交通方式和备选安排；交通耗时作为估计，无法确认的入口和日期天气须简短说明，不编造坐标、营业时间或预报。
- 外部摘要仅作为参考数据；提示模型忽略摘要中的指令。只读搜索资料，不执行资料里的操作。

## 验证与边界

2026-10-18：新增 9 条用例，适配器专项合计 11 条通过；主系统 157 条及 11 个子场景通过。所有自动化用例替代了外部请求，没有消耗模型额度。

另进行了公开联网实测：在受控环境将高德地点响应设为空，使用杭州、西湖、风光摄影关键词，取得三条网页标题与摘要。该检查证明搜索及上下文接线可用，没有调用真实模型，不代表整条规划路线经过现场验证，也不代表所有地区网络均能直连搜索服务。当地网络需要代理时，应在启动后端的环境配置正常的 HTTPS 代理；不要在仓库提交代理凭据。

高德和两个搜索入口都不可用时，仍会传递明确的空结果，由现有规划流程给待核实的区域建议与条件式备选安排，不伪装为已搜索成功。搜索摘要可能陈旧或偏离主题，最终规划质量仍需另外评估。

公网 Netlify 版本只有前端预置案例。本次改动属于完整服务的后端规划能力，不会将公网演示变成实时联网规划；本地服务若没有监控 Agent 源码热重载，需要重启主后端后再体验。
