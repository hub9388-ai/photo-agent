# 猫咪圆润编辑不再强制画笔选区

日期：2026-10-18。对象：本地真实修图服务；Netlify 演示数据路径没有改动。

## 问题与规则

原画布摘要笼统要求“身形编辑必须在原图局部选区进行”，容易让规划模型将人像瘦身规则套到猫咪圆润修改。现有确定性人像关键词本身不包含“圆润”；没有完整复现用户那轮模型回复，因此不将这项提示词风险冒称为该轮唯一根因。

当前流程：

- 明确说“让猫变得圆润一些”等猫狗圆润要求，单一可见图片图层可以直接准备 `replace_region` 待确认计划，不调用文本规划模型，不先拆层。
- 无选区时按文字目标进行整图语义生成；有当前选区时保留并固定该选区。用户始终要点击执行计划后才提交图片模型。
- 多个可见图片图层时先明确目标；涉及人物、瘦身、否定圆润或只读核对的指令不走该快捷路径。识别使用有限文本规则，不是图片主体检测，也不声称覆盖任意说法。
- 人物瘦身仍要求原图局部有效选区与执行确认，原有版本、坏候选和透明缺口保护保留。

没有蒙版的语义编辑不能保证背景和其他像素绝对不变。提示词要求保留主体特征、姿态、背景与摄影质感，但不能将提示词当作像素保真保证；需要精确区域约束时仍可主动使用笔刷。

- 完整自动化测试由 197 条增加到 **200 条，本次全部通过**；独立修图 38 条，人物保护文件 12 条。不是模型生成质量验收。

- 原图素材与修订号未变化；没有点击执行，没有请求文本模型或图片模型。报告保存在本地忽略目录 `.test_artifacts/portrait-guards/report.json`。

## 使用

刷新本地修图页。若不想沿用旧选区，先点“清除”，再发送“让猫变得圆润一些，保留花纹、姿态和背景”，检查待确认计划后执行。旧对话提示不会自动改写，需发送新指令；点击执行会使用图片模型额度。本轮没有替用户生成新图片。
