# Post 建议载入现有调色面板

## 使用

1. 在真实照片分析结果中点击“将当前照片送入修图工作台”。链接同时带 `media_id` 和 `job_id`。
2. 在修图服务登录后点击“发送素材库照片”。若另选本地文件，原照片的建议不会跟随，以免串图。
3. 右侧“调色”面板自动打开，载入近似初始值；可拖动滑杆预览、微调、重置。
4. 点击“应用”后调用本地 `adjust_image`，成功后形成可撤销的新版本；图片可通过原有导出功能保存。
5. 右侧“编辑记录 → 调色 → 查看 Post 转换与实际应用值”查看来源任务、原建议、转换初值、实际值及跳过项。

导入不自动写入图像、不把参数文本发给聊天模型、不在旧版本上自动重放建议。现存旧会话不会补写来源或改动照片；需要从分析页重新导入这条链路。

## 转换策略 `post-sliders-v1`

输入只接受保存的成功 Post 结果中的结构化 `xmp_params`；不从长篇文字、方向说明、数值区间中猜值。接口核对任务仅包含目标照片；批量分析暂不猜测对应关系。

| Post 字段 | 工具字段 | 近似规则 | 初始幅度限制 |
| --- | --- | --- | --- |
| Contrast2012 | contrast | 原值 / 100 | ±0.25 |
| Highlights2012 | highlights | 原值 / 100 | ±0.40 |
| Shadows2012 | shadows | 原值 / 100 | ±0.35 |
| Saturation | saturation | 原值 / 100 | ±0.30 |
| Vibrance | vibrance | 原值 / 100 | ±0.20 |
| Clarity2012 | clarity | 原值 / 100，暂只自动接受非负值 | 0～0.20 |

这是确定的产品初始值策略，**没有完成摄影软件到 Pillow 的视觉幅度标定**。不是 Lightroom 等价转换，也不宣称更好看。输入须是 -100～100 的有限数值；零值保持零，方向保持正负。限幅会记录。

黑色色阶、白色色阶、去朦胧、HSL、曝光 EV、色温 Kelvin 等没有确认规则的字段明确跳过并保留原值与原因，不替代成全局亮度、锐化或其他参数。用户仍可手动使用现有面板的亮度、色温等滑杆。

现有清晰度、锐化依赖后端卷积，不能实时预览，应用后查看并可撤销；其他项复用已有画布预览。实时预览与导出仍可能有取整、采样差异，视觉质量另做评测。

## 数据与执行边界

- 主服务 `GET /api/jobs/{job_id}/retouch-advice?media_id=...` 只读取保存结果并确定转换，不调用模型。
- iframe 延续 origin/source/requestId 校验，只增加数值建议和任务标识，不跨域发送密钥。
- 草稿按编辑会话存入浏览器 sessionStorage；关闭标签页后可能丢失。切换会话隔离、画布版本变化不重放；成功应用后标记已应用，失败保留微调值。
- `advice_context` 是有长度限制的客户端来源记录，不作为执行权限或参数来源。实际数字参数单独提交，既有工具任务和历史记录持久化保存二者。
- `expected_revision` 在任务执行前校验，避免已经变动的画布套用旧预览。两项元数据不暴露给规划模型，也不会传给 Pillow。
- 局部换背景、人物形态等生成式操作继续使用原有大模型路径。此链路省去一次调色规划，不代表分析或生成式操作免费。

- `tests/test_retouch_adjust_draft.py`：元数据不会进入像素工具、版本冲突在读取图像前拒绝、实际微调值原样执行。
- `scripts/check_post_advice_ui.cjs`：建议协议、会话隔离、微调存储及应用状态；不是浏览器视觉验收。
- `scripts/check_retouch_adjust_draft.py`：64×48 合成图的真实本地 API/队列/历史/撤销验收，模型请求为零。报告 `.test_artifacts/post-sliders/report.json`。
- 此前双猫真实任务接口已核对：`Shadows2012=-10 → shadows=-0.10`；`Blacks2012`、`Dehaze` 跳过。
- `python evaluations/001-shadow-direction/check_converter.py`：生产转换代码重放第一条用例的 15 项方向/跳过规则全部通过；报告标注 `not_executed`，没有冒充新执行的 Agent 轨迹，也未改写历史失败记录。

没有对用户原照片执行新的生成调用，也未宣称已经完成浏览器端端到端视觉验收。上游修改同步保存于 `integrations/retouch-photoai.patch`，未提交或推送 GitHub。
