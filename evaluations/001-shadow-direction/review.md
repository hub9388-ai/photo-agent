# 复盘：从截图到可重复评测

## 问题分析

用户看到调色执行成功，但怀疑实际效果不符合摄影建议。最初的截图判断只是假设；随后只读查询工具表、规划表及既有 Post 结果，才确认实际调用。

已验证的事实：

- `Shadows2012=-10` 被执行为 `shadows=+0.12`，符号反转。
- 规划与执行记录一致，因此不是执行器又偷偷改写了参数。
- 该会话只有一次 adjust_image，不能套用此前另一张猫图的“重复调色”原因。
- 规划回复明确称用全局亮度/对比度替代黑场、用清晰度/锐化模拟去朦胧。
- 原分析目标是忧郁沉闷，压暗、降饱和并非天然错误；核心问题是转换缺乏约束、忠实性不可保证。

另一个真实问题是输入中含矛盾：“阴影降低 -10”，后面通用解释却是“提亮暗部”。它可能影响规划，但没有对照实验，不能宣称是唯一根因。

## 方案选择

| 方法 | 价值与局限 | 本轮选择 |
| --- | --- | --- |
| 看截图、人工判断 | 能发现视觉异常，无法证明真实入参 | 保留作为线索 |
| 只统计工具 succeeded | 易做，却漏掉本例语义错误 | 不作为质量结论 |
| 固定记录与规则判定 | 可重复、无需费用，适合检查方向/范围 | 本轮实现 |
| 让另一个模型评分 | 可辅助解释和审美，但有成本及判断波动 | 本轮不需要 |
| 每次重跑完整修图 | 覆盖真实系统，但慢且会消耗模型额度 | 后续分阶段做 |

## 实现与验证

本轮只建立评测资产：case、真实历史字段、判定器、人工正向对照、判定器回归测试。历史记录应稳定判失败；人工记录通过只说明判定器存在可通过路径。

失败检查应为5项，但它们来自同一任务，有相关性：黑场替代同时触发 brightness 越界约定和 unsupported.Blacks2012 两项。不要据此计算“准确率10/15”或对外报告任务成功率。

源码审计还显示原 Post 文字建议中的曝光、冷调、绿色 HSL、暗角未完整进入提交参数文本。本例只评测已经传递的8项，不把丢失内容当成修图助手收到却未执行；传递完整性应另建用例。

## 本次尚未完成什么

- 没有修复生产转换逻辑，也没有让当前 Agent 再次生成计划。
- 没有校准 Lightroom/XMP 与 Pillow 的参数幅度。
- 没有证明图片更好看，或测出整个系统的准确率、延迟分布和成本收益。
- 没有识别所有“看似解释合理但行为错误”的自然语言变体。
- “明确跳过”需要真实运行提供证据，不能只凭自报就认定工具行为正确。

## 下一次迭代的明确目标

只修复建议到工具的转换约定：保留参数名、单位、方向与能力限制，不让模型自行发明替代关系；消除前端方向矛盾的通用说明。先对本例采集一份真实新规划，再用此判定器检查。另行设计“先澄清而不执行”的用例，避免把合理的澄清策略误判为错误。

需要保留的证据：新旧代码版本、case版本、原始输入、新的真实计划/工具参数、判定报告。图片验收另存原图与结果，明确人工审美与规则检查的不同结论。
